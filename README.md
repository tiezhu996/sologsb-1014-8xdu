# 格致 · 数学证明步骤编写与检查工具

一个完全在浏览器运行的数学证明工作台。使用步骤、引用和推理规则组织证明，实时检查结构与符号，并保留版本快照。

## 功能

- 逐步录入前提、推导和结论，选择推理规则并维护步骤引用。
- 检查未定义符号、缺失引用、循环引用和未证明目标。
- 为步骤记录旁注、反例和替代分支。
- 公式快捷输入、KaTeX 实时渲染、原生拖拽排序与键盘导航。
- 文档级撤销/重做，`localStorage` 自动保存，多版本文档管理。
- 保存版本快照并进行逐步差异比较。
- 离线分支合并：导出时留下共同基线快照，导入时按稳定步骤编号三向合并。
- 导出 Markdown 或 LaTeX 证明稿。

## 离线分支合并

不同电脑上批改同一份证明稿时：

1. 在当前稿点击 **导出分支包**：系统会先把当时的完整状态（步骤、引用、符号表、目标）作为**共同基线快照**留在文档中，再下载 `.gzhi.json` 离线包带走。
2. 其他电脑在包上继续批改（包本身仍含基线快照）。
3. 回到本机点击 **导入合并** 并选择批改包：
   - 以基线快照为共同祖先做三向合并；**只改一处**的改动（步骤内容、引用增删、符号含义、证明目标）自动接收。
   - 一方撤去步骤、另一方在基线之外新增对该步骤的引用时，会列入**待处理**：选择“恢复被删步骤并接上依据”或“保留删除并摘除引用”。正式证明永远不会写入断掉的依据。
   - 同一符号/步骤被双方改成不同内容时，列入待处理，二选一。
   - 步骤顺序按基线顺序稳定贴回，两侧新增步骤依次追加。
4. 待处理项全部解决后才能 **确认合并写入**：步骤、引用和基线快照在一个事务中原子落盘；快照按 ID 去重，中途失败或重复重试都不会产生副本。
5. **旧稿兼容**：若当前稿找不到包中的基线快照（例如包来自更早的导出），仍可导入——系统把当前稿已有步骤与符号当作共同内容合成基线，只接收另一侧的新增与单方改动，不会反向删除本地内容。

## 技术栈

- Mithril 2
- TypeScript
- Bulma
- KaTeX
- Vite

## 本地开发

```bash
npm install
npm run dev
```

浏览器打开终端输出的开发地址。数据保存在当前浏览器的 `localStorage` 中。

## 生产构建

```bash
npm run build
npm run preview
```

构建产物位于 `dist/`。

## 键盘操作

| 快捷键 | 操作 |
| --- | --- |
| `Ctrl/Cmd + Enter` | 添加推导步骤 |
| `Ctrl/Cmd + Shift + Enter` | 添加结论步骤 |
| `Alt + ↑ / ↓` | 切换当前步骤 |
| `Ctrl/Cmd + Z` | 撤销 |
| `Ctrl/Cmd + Shift + Z` 或 `Ctrl/Cmd + Y` | 重做 |
| `Ctrl/Cmd + S` | 立即保存 |
| `Delete` | 删除当前步骤（编辑框外） |

## Docker

镜像内由 nginx 监听容器端口 `80`，不包含或硬编码宿主端口。

```bash
docker build -t math-proof-editor .
docker run --rm -p 10014:80 math-proof-editor
```

宿主端口 `10014` 仅用于本地运行示例，实际编排端口以根端口表为准。
